# ADR-0002 — Authenticate with a KSeF certificate and a XAdES signature, not a KSeF token

Date: 2026-11-26
Status: accepted

## Context

KSeF API 2.0 offers two non-interactive ways to authenticate: a KSeF token, or a XAdES-signed `AuthTokenRequest`. Under the regulation in force, KSeF tokens authenticate only until 2026-12-31; an amendment extending them is announced but not published. A KSeF certificate of type `Authentication` can be generated by the owner in Aplikacja Podatnika (RSA-2048 or EC P-256 key, valid up to two years, revocable). KSeF verifies its own certificates internally, without an OCSP/CRL wait. The TEST environment accepts self-signed certificates, so the full flow can be verified before any real credential exists.

## Decision

Authenticate every run with the owner's KSeF `Authentication` certificate: challenge, enveloped XAdES-BES signature over `AuthTokenRequest` (`SubjectIdentifierType=certificateSubject`, context = the owner's NIP), status polling, token redeem. Support both RSA (rsa-sha256) and EC P-256 (ecdsa-sha256 with a raw `R || S` signature value). The certificate is a PEM file and the private key an encrypted PKCS#8 PEM file, both outside the repo; the key password lives in the macOS login Keychain and is read at runtime. No access or refresh token is persisted between runs.

## Consequences

- The tool keeps working after 2026-12-31 regardless of the token regulation.
- **A KSeF certificate has no permission scope.** Unlike a token, which can be limited to `InvoiceRead`, the certificate authenticates the owner as a person and carries all of their rights in the NIP context, including issuing invoices. Whoever has the key file and its password can act as the owner in KSeF. Hence: key file mode `0600` outside the repo, password only in Keychain, minimal pinned dependencies, and revocation in Aplikacja Podatnika if the Mac is lost or the key leaks.
- XML canonicalization and signing are needed (ADR-0004 picks the library).
- The owner must renew the certificate at least every two years; an expired certificate shows up as a failed-run notification.
- `GET /auth/{referenceNumber}` is used now; it sunsets 2027-06-15 and must be switched to `/auth/rev2/{referenceNumber}` once that is on PROD.
