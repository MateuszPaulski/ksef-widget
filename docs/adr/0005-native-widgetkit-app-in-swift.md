# ADR-0005 — Native WidgetKit desktop widget in a small Swift app, ad-hoc signed, next to the TypeScript fetcher

Date: 2026-11-26
Status: accepted

## Context

The owner wants the latest KSeF invoices visible on the macOS desktop and kept roughly current. Options: a native WidgetKit widget, a menu-bar item, or a third-party HTML widget host. A WidgetKit widget must ship as an extension inside an app. The fetcher is TypeScript on Node 22 (ADR-0001) and stays the only code that talks to KSeF. The repository is public. The owner's Mac has Xcode 27.1, Swift 6.4 and XcodeGen; another ad-hoc-signed widget app installed in `~/Applications` on that Mac is live and reloaded by `chronod` all day. Design: `docs/superpowers/specs/2026-11-26-ksef-desktop-widget-design.md`.

## Decision

- A native WidgetKit widget (medium and large sizes) in a minimal host app, written in Swift with SwiftUI and AppKit, no third-party Swift dependencies. It only renders a local snapshot written by the fetcher (ADR-0006); it never contacts KSeF and never reads the certificate.
- The Swift code lives in `widget/` in this repository. The Xcode project is generated by XcodeGen from the committed `widget/project.yml`; the generated `.xcodeproj` and the build directory are gitignored. Builds and tests run with `xcodebuild` from the command line.
- The host app is an `LSUIElement` agent with no window: it forwards widget link clicks to the default browser (only `https` URLs on the three KSeF QR hosts) and, on a plain launch, shows one alert telling the owner how to add the widget.
- Signing is ad hoc ("Sign to Run Locally", `CODE_SIGN_IDENTITY = "-"`), committed in `project.yml`. No Team ID, signing identity or provisioning profile is stored anywhere in the repository. The owner installs the built app into `~/Applications`.

## Consequences

- A second language and toolchain (Swift, Xcode, XcodeGen) in a TypeScript project; the two halves share only a JSON file contract.
- macOS decides when the widget redraws (minutes, not seconds).
- Building never touches the Keychain and the public repository holds nothing personal. If macOS ever rejects ad-hoc widget extensions, Developer ID signing can be passed on the `xcodebuild` command line without changing committed files; that would be a new decision.
- The app is not notarised and not distributable; it runs only on the Mac that built it, which is all a personal tool needs.
- A widget click opens the host app briefly (the system delivers widget URLs to the containing app), which then opens the browser and quits.
